# DigitalLifeEngine - 数字生命引擎

## 项目用途

这是一个 **AI 桌宠数字生命引擎** 的早期版本（当前为 V0.5）。

目前已实现 **每日行为记录、状态推断、长期用户画像、历史分析和桌宠成长**：

- 用户通过命令行输入每天的行为数据
- 程序根据数据计算学习指数、活跃指数、互动指数
- 程序分别判断行为活跃状态和综合生活状态
- 数据自动保存到 JSON 文件，支持多天记录追加
- 输入带合法性检查，输错不会崩溃，会提示重新输入
- 同一天重复运行会询问是否覆盖，不会产生重复记录
- 显示结果后暂停，按 Enter 键才退出，方便查看结果
- V0.2 新增：历史表现分析（平均值统计、连续记录天数、指数趋势）
- V0.3 新增：桌宠成长系统（经验值 XP、等级、亲密度、升级提示）
- V0.4 新增：心情、精力、压力采集，可解释状态推断与个性化建议
- V0.4 新增：向上层桌宠输出 `pet_reaction` 反应代码
- V0.4 改进：拒绝 `nan` / `inf`，历史分析按日期排序，保存过程更安全
- V0.5 新增：根据全部记录自动生成长期用户画像
- V0.5 新增：长期特征、最近 7 条记录、主导状态和陪伴策略
- V0.5 改进：新增或覆盖记录时完整重算画像，避免累计误差

> 本项目专为 Python 初学者设计，不使用任何复杂框架，只用 Python 标准库。

## 如何运行

1. 打开终端（命令行）
2. 进入项目目录：

```bash
cd DigitalLifeEngine
```

3. 运行程序：

```bash
python main.py
```

4. 按照提示依次输入：

```
今天学习了几小时？ 3
今天玩游戏多少分钟？ 45
今天完成了几个任务？ 4
今天与桌宠互动了几次？ 6
今日心情（1=很差，5=很好）： 3
今日精力（1=很疲惫，5=很充沛）： 2
今日压力（1=很轻松，5=压力很大）： 4
```

5. 程序会显示今日分析、桌宠状态、历史表现和长期用户画像，并将数据保存到 `data/behavior_data.json`。
6. 查看完结果后，按 **Enter** 键退出程序。

运行自动测试：

```bash
python -m unittest -v
```

> 提示：输入错误（比如输成了字母、负数或小数填进整数字段）不会让程序崩溃，
> 程序会提示你重新输入，直到输入合法为止。

## 程序目前实现了什么

### 输入项

| 输入项 | 类型 | 说明 |
|--------|------|------|
| 学习时间 | 小时（支持小数） | 今天学习了几小时 |
| 游戏时间 | 分钟（支持小数） | 今天玩游戏多少分钟 |
| 完成任务 | 整数 | 今天完成了几个任务 |
| 互动次数 | 整数 | 今天与桌宠互动了几次 |
| 今日心情 | 1～5 的整数 | 1 表示很差，5 表示很好 |
| 今日精力 | 1～5 的整数 | 1 表示很疲惫，5 表示很充沛 |
| 今日压力 | 1～5 的整数 | 1 表示很轻松，5 表示压力很大 |

### 计算指标

| 指标 | 计算规则 | 范围 |
|------|----------|------|
| 学习指数 | 每小时 10 分，最高 100 分 | 0 ~ 100 |
| 活跃指数 | 游戏每 10 分钟 2 分 + 每任务 10 分，最高 100 分 | 0 ~ 100 |
| 互动指数 | 每次互动 10 分，最高 100 分 | 0 ~ 100 |

### 行为活跃状态

| 状态 | 条件 |
|------|------|
| 积极 | 三个指数平均分 >= 70 |
| 一般 | 三个指数平均分 >= 40 且 < 70 |
| 低活跃 | 三个指数平均分 < 40 |

行为活跃状态只描述学习、任务和互动表现，不直接等同于情绪状态。

### 综合状态推断（V0.4 新增）

程序结合心情、精力、压力、当日行为和最近三条有效历史记录，推断四种综合状态：

| 综合状态 | 主要判断依据 | 桌宠反应代码 |
|----------|--------------|--------------|
| 压力偏高 | 今日压力达到 4～5 分 | `comfort` |
| 疲惫 | 压力未达高位，但精力只有 1～2 分 | `rest` |
| 充实 | 心情和精力较好，压力较低 | `celebrate` |
| 平稳 | 其他正常波动情况 | `encourage` |

系统会同时保存和显示：

- `inferred_state`：综合状态；
- `state_reasons`：可解释的判断依据；
- `recommendation`：建议类型、标题和难度；
- `pet_reaction`：供桌宠界面读取的反应代码。

这属于生活状态推断，不是医学或心理诊断。

### 历史数据分析（V0.2 新增）

每次记录完今天的数据后，程序会自动显示 **"历史表现分析"** 区域，包含三部分内容：

**1. 平均值统计**

| 统计项 | 说明 |
|--------|------|
| 累计记录天数 | 一共保存了多少天的记录 |
| 连续记录天数 | 按"日期是否连续"计算，不是简单数记录条数 |
| 平均学习时间 | 所有记录的学习小时数平均值 |
| 平均游戏时间 | 所有记录的游戏分钟数平均值 |
| 平均完成任务 | 所有记录的任务数平均值 |
| 平均互动次数 | 所有记录的互动次数平均值 |
| 平均学习 / 活跃 / 互动指数 | 三个指数各自的平均值 |

**2. 趋势分析**

比较方法：**最近 3 天的平均值** 与 **此前所有天的平均值** 比较。

三个指数（学习、活跃、互动）分别显示趋势箭头：

| 箭头 | 含义 |
|------|------|
| `↑` | 最近 3 天明显更高（差值超过 5 分） |
| `↓` | 最近 3 天明显更低（差值超过 5 分） |
| `→` | 变化不明显（差值在 5 分以内） |

**3. 数据不足时的表现**

- 记录不足 4 天时（趋势分析需要"最近 3 天 + 此前至少 1 天"），
  程序会提示"历史数据不足，暂时无法分析趋势"
- 不会报错，平均值统计仍然正常显示

**连续记录天数示例**

- 记录日期为 8/23、8/24、8/25 → 连续记录 3 天
- 记录日期为 8/23、8/25（中间断了一天）→ 连续记录 1 天

### 长期用户画像（V0.5 新增）

每次新增或覆盖记录后，程序都会根据全部 `records` 重新生成 `user_profile`。画像不是累加器，因此覆盖旧数据不会造成重复计算。

画像分为两类信息：

| 区域 | 作用 |
|------|------|
| `long_term` | 全部历史记录的长期平均值和主导状态 |
| `recent_7_records` | 最近 7 条记录的状态，用于调整当前陪伴策略 |

为避免根据少量数据轻率地下结论，画像分为三个成熟阶段：

| 有效主观状态样本 | 画像成熟度 |
|------------------|------------|
| 少于 3 天 | 数据积累中 |
| 3～6 天 | 画像形成中 |
| 7 天及以上 | 画像较稳定 |

画像可能生成“学习投入较高”“任务执行力较强”“更偏好低频陪伴”等标签，并输出以下陪伴模式：

| 模式 | 使用场景 |
|------|----------|
| `observe` | 数据不足，继续观察，不下长期结论 |
| `reduce_load` | 近期压力偏高，降低推荐任务负担 |
| `recovery` | 近期精力偏低，优先休息恢复 |
| `growth` | 近期状态良好，提供适度挑战 |
| `steady` | 状态平稳，维持当前节奏 |

当前建议会附带 `profile_context`，让上层桌宠知道这条建议参考了什么长期背景。

### 桌宠成长系统（V0.3 新增）

每天成功记录数据后，桌宠会根据你的行为获得成长。成长分三个方面：

**1. 经验值（XP）**

| 行为 | XP |
|------|-----|
| 每完成 1 个任务 | +10 |
| 学习时间每满 1 小时 | +5 |
| 每与桌宠互动 1 次 | +2 |
| 当日学习指数达到 70 | 额外 +10 |
| 当日连续记录达到 3 天 | 额外 +10 |

> 学习时间不足 1 小时的部分不计入 XP（例如 2.5 小时按 2 小时计算）。

**2. 等级**

根据**累计 XP** 判断等级：

| 累计 XP | 等级 |
|---------|------|
| 0 ~ 99 | Lv.1 |
| 100 ~ 199 | Lv.2 |
| 200 ~ 349 | Lv.3 |
| 350 ~ 499 | Lv.4 |
| 500 ~ 699 | Lv.5 |
| 700 以上 | Lv.6+ |

如果某次运行让桌宠升级了，程序会显示升级提示，例如：

```
恭喜！桌宠升级了！
Lv.2 → Lv.3
```

**3. 亲密度**

| 行为 | 亲密度 |
|------|--------|
| 每与桌宠互动 1 次 | +1 |
| 每完成 1 个任务 | +1 |
| 每天成功记录数据 | +1 |
| 当日学习指数达到 70 | 额外 +2 |

亲密度范围是 **0 ~ 100**，达到 100 后不再增加。
显示时会附带今日变化，例如 `亲密度：68 / 100（+4）`。

**4. 桌宠状态输出示例**

```
----------------------------------------
              桌宠状态
----------------------------------------
等级：Lv.3
经验值：245 XP
亲密度：68 / 100（+4）

今日获得 XP：17
----------------------------------------
```

**5. 防刷机制**

如果同一天重复运行并选择**覆盖**今天的记录，程序会先扣掉旧记录对应的 XP 和亲密度，再按新记录计算。所以反复覆盖不会重复获得成长值。

**6. 旧数据兼容**

- 旧版本数据文件只有 `records`，没有 `pet` 字段
- 程序第一次读到这种文件时，会自动创建默认的桌宠数据（XP 0、Lv.1、亲密度 0）
- 已有的 `records` 数据完全不受影响

### 数据存储

- 数据保存在 `data/behavior_data.json` 文件中
- 如果文件或目录不存在，程序会自动创建
- 每次运行保存当天记录：新的一天追加新记录，同一天重复运行会先询问是否覆盖

### 输入合法性说明

程序会对每一项输入做检查：

| 输入情况 | 程序行为 |
|----------|----------|
| 输入的不是数字（如 `abc`） | 提示输入无效，要求重新输入 |
| 输入负数（如 `-3`） | 提示数字不能小于 0，要求重新输入 |
| 任务数 / 互动次数输入小数（如 `3.5`） | 提示输入无效，要求重新输入（这两项只接受整数） |
| 心情 / 精力 / 压力超出 1～5 | 提示超出范围，要求重新输入 |
| 输入 `nan`、`inf` 或 `-inf` | 提示必须输入有限数字 |

程序不会因为错误输入而崩溃，会一直询问直到输入合法为止。

### 同一天重复记录的处理方式

如果同一天运行程序多次，程序会检测到今天已有记录，并询问：

```
是否用新数据覆盖今天的记录？（y/n）
```

- 输入 `y`：用新数据**覆盖**今天的旧记录，不产生重复记录
- 输入 `n`：直接退出，今天的记录保持不变
- 输入其他内容：提示重新输入

### 程序结束时的暂停

程序显示完分析结果后**不会立即退出**，会显示：

```
按 Enter 键退出...
```

按 Enter 键后程序才会关闭。这样即使双击 `.py` 文件运行，也能看清结果，窗口不会一闪而过。
